# Kairos — UI rules

Part of the project rules (see AGENTS.md). Full spec: SPEC.md §14.

## 3B. UI quality bar (full spec in SPEC.md §14)

- **Two modes, one app.** *Assistant mode* is the default and must feel like a polished consumer product: calm, fast, warm plain-language copy, voice-first, mobile-first, honest about gaps. *Inspector mode* exposes the engine for judges (Timeline, telemetry, Race view, results). One toggle switches between them without interrupting the session.
- The UI must make three things felt by a customer and obvious to a judge: **it's already answering while you talk** (the Answer Canvas, SPEC.md §14.3a), **every part of your question gets answered** (intent colour threading), and **every sentence has a source and gaps are admitted**.
- Every animation and state change is driven by a real pipeline event. Nothing is faked with timers, and Story mode runs the real pipeline.
- Drafts shown before the user finishes speaking are always visibly provisional, and the user can turn them off ("Show answer while I speak"). In voice-output contexts drafts are never spoken.
- Default visual direction: "Calm Precision" (SPEC.md §14.3a). Colour carries meaning (intents, states), never decoration.
- UX quality is **measured**: a 5-person hallway test with a System Usability Scale (SUS) score, recorded honestly in `docs/UX_TEST.md` (TBD until it's run).
- Original Kairos branding only. No Samsung logos, product names or trade dress in the UI.
- React + TypeScript (strict) + Vite + Tailwind CSS, accessible primitives from Radix UI. Built in a multi-stage Docker build and served as static files by FastAPI — no Node at runtime, no CDN at runtime, fonts self-hosted.
- Must meet WCAG 2.2 AA: keyboard-only operation, visible focus, 4.5:1 contrast, `aria-live` for streamed answers, `prefers-reduced-motion` respected.
- Every view has designed empty, loading, error and reconnecting states. Never a blank screen or a raw error.
- Every number on screen is read from the API or from `runs/` output files.
- Lighthouse (desktop and mobile) ≥ 90 for Performance, Accessibility and Best Practices; zero axe violations in Playwright tests.
- Polish beats breadth: if time is short, perfect Assistant mode, Story mode and the Timeline before adding any other Inspector screen.
