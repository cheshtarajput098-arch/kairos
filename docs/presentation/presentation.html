Existing Solutions & Gaps

Critical Vulnerabilities in Conventional Voice RAG

Standard sequential batch architectures break under conversational speech dynamics:

3.5 – 5.0 s
Sequential Delay
Listen -> Wait for silence -> ASR -> Vector search -> LLM generation leaves users stranded in silence after speaking.
Failure
On Compound Queries
Complex questions ('What is the ballroom capacity and AV cost?') are sent as one noisy vector search, missing sub-clauses.
100% Waste
Full State Discard
Late detail corrections ('Actually, make that international') force conventional systems to discard state and re-execute entire turns.

Our Solutions & Architecture Diagram

Parsimonious 5-Stage Live Streaming Pipeline

Zero external agent frameworks (no LangChain, no LlamaIndex). One Python 3.11 asyncio event loop running locally on CPU:

Pipeline: Live Speech Chunks ──► Stage 1: Controller (WAIT/RETRIEVE/SUPPRESS) ──► Stage 2: Intent Decomposer ──► Stage 3: Hybrid Retriever (BGE+BM25) ──► Stage 4: RRF Fusion ──► Stage 5: Two-Speed Synthesis ──► Grounding Gate ──► Session Delta Engine ──► Answer Canvas UI
Speaker Note: "Our architecture follows strict architectural parsimony: one asyncio event loop, five stages, zero framework bloat. Every stage has a justified microsecond budget."

Brownie points slide (differentiation)

What Makes Kairos Uniquely Different

Four architectural breakthroughs engineered specifically for live streaming voice RAG:

1. Answering While You Speak
Ready-at-End: 65.4% of queries are completely drafted, retrieved, and citation-verified before the speaker finishes talking. Zero awkward conversational delay.
2. Two-Speed Grounded Synthesis
Instant Speed 1 verbatim excerpt (< 1ms) followed by fluent local Qwen2.5 Speed 2 rewrite (< 820ms). Both pass the strict Grounding Gate with zero hallucinations.
3. In-Place Session Delta Engine
When late details or corrections arrive, Kairos patches only the affected claim. Unaffected claims remain 100% byte-identical (Gate G5 PASS), saving 100% restart waste.
4. 100% Offline Local CPU Execution
Requires zero network connection, zero cloud API keys, and zero GPU. Fully reproducible in Docker (`docker run --network none kairos make eval`).
Speaker Note: "Our four differentiators: Answering while you speak, two-speed grounded synthesis, in-place delta state preservation under Gate G5, and 100% offline CPU reproducibility."
